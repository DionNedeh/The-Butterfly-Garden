## Backend and integration corrections

- New gardens start with the current free backdrop defaults, avoiding a redundant save immediately after loading an otherwise unchanged garden.
- Stored image byte counts and dimensions are exact integers; image declarations cannot understate their payload size. Corrected a backend test fixture that declared 24 bytes for a 23-byte payload.
- Backup restoration verifies the actual image format, dimensions and decode before replacing the current garden. Corrupt media is rejected rather than silently discarded.
- Custom-image save feedback waits for the repository write. Quota failure retains the editor draft and restores the previously persisted image/selection while keeping unrelated edits. Concurrent image-save requests are rejected with a retry message.
- Built-in scene load failure falls back to Sunlit Meadow; the saved selection remains intact. Personal-image failures retain the image in backups and explain the fallback.
- New crop/image objects remain in their own collection. Existing repository tests enforce zero image bytes in unrelated writes.
- Navigation and onboarding reset scroll position; explicit Show seed navigation scrolls to the requested seed tray.

Initial JS+CSS increased **7.5%**, within the plan's proposed 10% gate.

single observations, so do not infer a significant speed difference from them.

## Review locally

Open `http://127.0.0.1:4173/The-Butterfly-Garden/` while the production preview is
running. To restart: `npm run build`, then `npm run preview -- --host 127.0.0.1`.

Suggested review sequence:

1. Garden in sunlight/night mode; narrow the browser to a phone width.
2. Shop → Boutique: search Daisy Bonnet, Try on, switch life stage; inspect Jars and Flight.
3. Shop → Backdrops: choose Cottage Bloom or a Pass scene; add a personal image, crop it, save, reload, then download a backup from Settings.
4. Guide: search Queen and use Show Milkweed seed. No planting occurs until you explicitly choose to plant.
5. Care and Journal: check readability, outfit positioning and timeline dots.
6. Settings → What's new; confirm the release accurately describes the visible features.

## Remaining release checks and boundaries

- Physical Android phone/PWA installation, touch feel, device memory/thermal behavior, OS-specific file pickers and display cutouts have not been tested. Pixel 7 emulation is not a physical device.
- Safari/iOS, Firefox, and native Android packaging are not certified by this pass.
- Actual service-worker upgrade between two deployed releases and store/provider billing were not exercised. Offline launch and schema migration were exercised against local production builds.
- Schema 6 is intentionally unreadable by older app builds. Preserve a backup before updating; rollback requires a compatible app or a pre-upgrade backup, not simply serving 2.0 over a 3.0 garden.
- No GitHub push, deployment, external upload, purchase or subscription activation was performed. No new runtime dependency was added.
- Keep the existing `gardenPass.ts` provider interface for future verified access. Native packaging, receipt verification, account/recovery design, subscription lifecycle and current Google Play policy review need their own later implementation and approval.
